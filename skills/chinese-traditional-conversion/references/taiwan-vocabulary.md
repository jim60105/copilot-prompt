# 臺灣語感在地化準則

字元與詞彙都換對之後，文字仍可能讀起來不像臺灣習慣的自然寫法。本檔處理字典表達不了的部分：介係詞的選擇、動賓結構的鬆緊、副詞的分佈與量詞習慣。

適用時機是 `convert.py` 跑完、MUST FIX 與 REVIEW 都處理完之後。**只調整語言在地化，不改寫論點、結構與語氣**；整體寫作規範與風格引導屬於 `chinese-content-writing-guideline` 的職責，兩者不重疊。

## 介係詞與連接詞

### 通过 → 透過｜藉由｜通過

作為介係詞表示途徑或手段時取「透過」或「藉由」；表示穿越實體空間、考試及格或法案審核核可時保留「通過」。

- 改前：通过配置文件来控制行为。
- 改後：透過設定檔控制行為。
- 不動：這項提案已經通過立法院審查。

### 基于 → 根據｜基於｜以…為基礎

表推論依據、技術基礎時，陸式習慣起手「基于」，臺式偏好「根據」、「依照」或「以…為基礎」；只有哲學或法理概念（如「基於誠信原則」）保留「基於」。

- 改前：基于该算法，我们可以得出结论。
- 改後：根據這項演算法，我們可以得出結論。
- 改前：系统基于 Linux 开发。
- 改後：系統以 Linux 為基礎開發。
- 不動：基於人道考量，給予專案救助。

### 针对 → 針對｜就…而言｜對於

陸式書面語頻繁以「针对」開頭，臺式在說明範圍或對象時，常使用「對於」、「就…而言」或直接省略。

- 改前：针对这种情况，我们需要调整策略。
- 改後：面對這種情況，我們需要調整策略。
- 改前：针对初学者，本书提供了入门指南。
- 改後：本書為初學者提供了入門指南。
- 不動：針對這項指控，發言人提出反駁。

### 以及 vs 及其、和、與

陸式常見「A，以及 B」跨句連用，臺式在短語並列時多用「與」、「和」；帶所屬關係時用「及其」。

- 改前：系统支持用户管理，以及权限分配。
- 改後：系統支援使用者管理與權限分配。
- 改前：研究模型以及其参数。
- 改後：研究模型及其參數。

## 動賓結構的鬆綁

陸式公文與技術書面語偏好「虛動詞 ＋ 動作名詞」的複合框架（如「對…進行…」、「作出…」），臺式書面語偏好直接使用及物動詞，行文更精煉俐落。

### 对…进行… → 直接動詞

- 改前：对数据进行清洗和分析。
- 改後：清洗並分析資料。
- 改前：对系统进行升级。
- 改後：升級系統。

### 作出 / 做出 → 提、給予、直接動詞

- 改前：对该问题作出解释。
- 改後：解釋該問題。（或：對該問題提出說明）
- 改前：作出决定。
- 改後：做出決定。（或：決定）

### 给予 / 予以 / 加以 → 直接動詞

- 改前：对违规行为予以惩处。
- 改後：懲處違規行為。
- 改前：对新员工给予培训。
- 改後：培訓新員工。
- 改前：对上述意见加以采纳。
- 改後：採納上述意見。

## 冗贅動詞的刪除

公文式套語中的推進型動詞（如「開展」、「實現」、「做好」），在臺式自然技術書面語中多半為贅字，可直接刪除或轉化。

### 开展 → 開始｜進行｜（刪除）

- 改前：积极开展各项测试工作。
- 改後：積極進行各項測試。（或：展開測試）
- 改前：开展深入调查。
- 改後：深入調查。

### 实现 → 達成｜完成｜（刪除）

非程式碼的「實作（Implement）」，而是公文式「實現了某目標」時，改為達成或直接敘述結果。

- 改前：实现了性能的显著提升。
- 改後：顯著提升了效能。
- 不動：在 Rust 中實現 Iterator Trait。（技術實作保留）

### 做好 / 抓好 → 完善｜落實｜（刪除）

- 改前：做好安全防范工作。
- 改後：落實安全防護。
- 改前：抓好质量管理。
- 改後：加強品質管理。

## 程度副詞與語氣詞

### 十分 / 极其 → 非常｜相當｜極為

陸式偏好「十分」、「极度」，臺式日常與技術書面語多偏好「非常」、「相當」或「極為」。

- 改前：该方案十分有效。
- 改後：該方案相當有效。（或：非常有效）
- 改前：极其重要的参数。
- 改後：極為重要的參數。

### 比较 / 还算 → 頗｜較為｜滿

陸式常以「比较」修飾一般程度（如「比较快」表示滿快的），臺式在技術文件中用「較」或「較為」，日常口吻用「滿…的」。

- 改前：这个库用起来比较方便。
- 改後：這個函式庫使用上較為方便。（口語：滿方便的）

### 挺…的 → 相當｜滿

- 改前：这个工具挺好用的。
- 改後：這個工具滿好用的。（正式書面：相當實用）

## 量詞與數詞

### 「个」的濫用與修正

陸式習慣將「个」泛化為萬用量詞，臺式中文偏好搭配具體精確的專用量詞（項、座、部、門、場、臺）。

- 改前：提出一个建议、建立一个机构。
- 改後：提出一項建議、建立一個機構。
- 改前：研发一个系统、制造一个汽车。
- 改後：研發一套系統、製造一輛汽車。

### 一下 / 一点 的使用差異

陸式常說「看一下」、「了解一下」，臺式在正式書面語中多省略口語助詞，或換成更莊重的動詞；若在友善介面提示中則保留自然語感。

- 改前：请用户阅读一下该协议。
- 改後：請使用者閱讀該協議。
- 友善提示可保留：點擊查看詳情。

### 序數與列舉形式

- 陸式常見「第1个」、「第一点是…第二点是…」。
- 臺式書面常見「第一、…第二、…」或「第一點、…第二點、…」。

## 不該動的情況

語感調整最容易越界的地方。以下情況一律保留原文，避免破壞精準度或失真：

### 1. 引用他人話語、法規條文、判決書、契約

引文必須忠於原始文字，不可擅自在地化句式。

- 例：《中華人民共和國公司法》第十五條：「公司可以向其他企業投資…」不得改動詞彙或虛詞。
- 例：引用原作者談話：「我們對此進行了深入探討。」保留引言原貌。

### 2. 專有名詞與機構名稱

即使其命名帶有陸式語感或特定框架詞，亦不可任意更名。

- 例：「中國質量認證中心」（不可改為「品質認證中心」）。
- 例：「面向對象程序設計學會」（專有名稱保留，即使術語為物件導向）。

### 3. 作者刻意使用的方言、時代語、角色語氣

文學作品、對話錄音或特定語境中的地方方言（如北京話兒化音、東北話詞彙）需保留角色特色。

- 例：小說角色台詞：「這事兒挺不落忍的。」不得擅改為「這件事令人相當難過」。

### 4. 技術規格與標準中定義明確的特定術語

國際標準、RFC 文件或特定協定定義之特定欄位與方法名稱，改動會導致程式或規格失去對應指涉。

- 例：HTTP Header `Referer`、OAuth 規範名詞、或是第三方 API 回傳之固定鍵值 `access_token`。
